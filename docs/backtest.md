# 기출문제 (과거 유증 백테스트) — Phase 1 + H1

실행: Actions → 유증 수집기 → Run workflow → command `backtest`, year `2020` … `2026` (한 해씩).
로컬: `python -m yujeung backtest --year 2020` → `data/backtest/2020.json` + 전체 합산 `data/backtest.json`.
year 를 비우면 합산만 다시 한다. 코드: `yujeung/backtest.py`.

## 대상
- 2020-01 ~ 2026-06 원공시의 DART 유상증자결정 중 **주주배정 계열**(주주배정증자 / 주주배정후 실권주 일반공모)
- 상장사: 법인구분 코스피·코스닥 + **현재 상장폐지(E)지만 종목코드가 있는 회사** (생존편향 방지). 당시 시장은 인수권 시장명으로 판단
- 정정공시는 해를 넘겨 120일까지 따라간다. 정정으로 시작하는 케이스(원공시가 전년도)는 전년도 실행 몫이라 뺀다
  - 꼬리 기간(해 넘어간 120일)은 **그 회사 케이스가 이미 있을 때만** 상세 조회(piicDecsn)한다. 케이스 없는 회사의 꼬리 공시는 어차피 지워질 케이스만 만든다
  - 케이스 있는 회사는 꼬리 원공시도 조회한다 — 이듬해 새 유증 원공시가 새 케이스를 열어야 뒤따르는 정정이 그해 케이스에 잘못 붙지 않는다
  - 생략 전후 비교: `python -m yujeung backtest --year 2020 --compare-tail` (감지 단계만, 저장 안 함, 다르면 실패)

## 미래 정보 금지
- **판정일 = 인수권 마지막 거래일** (운영의 가상 성과 스냅샷과 같은 순간)
- 영업이익: 판정일까지 **법정 제출기한이 지난** 마지막 보고서만 (`dart.op_income_asof`). 분기·반기 = 분기 말+45일(5/15, 8/14, 11/14), 사업보고서 = 다음 해 3/31. 실제 제출일보다 늦게 잡으므로 보수적 (일찍 낸 회사의 최신 실적을 못 쓰는 쪽으로 틀린다)
- 52주 위치: 공시일 직전 250거래일 (운영과 동일, 판정일보다 앞)
- 괴리율: 인수권 기간 당일의 KRX 인수권 종가·본주 종가·KRX 발행가(ISU_PRC)
- 판정: `verdict.py` 그대로 (`pipeline.live_verdict` 재사용). 가상 진입·측정: `paper.py` 그대로

## 채점
- 판정별(🟢🟡🔵⚪): 건수 · 승률 · 평균 · 중앙값 · 25/75 퍼센타일 · 최악 · 지수 대비 초과수익(%p)
  - 🟢⚪🔵 상장일 시가 / +5 / +20거래일, 🟡 +5 / +10 / +20거래일
  - 🟢?/🟡?(확인 필요, 판정 로직 v2~): 관문1 자동 항목 미확인이 있는 🟢/🟡 — 진입·측정은 🟢/🟡와 같고 따로 집계. 과거 기출에선 최대주주 청약·인수방식이 원문 휴리스틱이라 미확인이 많아 🟢 대부분이 🟢?로 갈 수 있다 → 🟢 vs 🟢? 비교가 곧 '미확인 포함 판정이 얼마나 틀렸나'
  - 수익률 분모는 투입 원금으로 통일: 🟢⚪🔵 인수권 종가+발행가, 🟡 상장일 종가. 🔵(인수권 매도)은 "팔지 않고 청약했다면"의 수익률이라 **낮을수록 판정 적중**(승률 = 청약 쪽이 이긴 비율). 어떤 판정도 −100% 밑으로 내려가지 않는다
- 필터 하나씩 떼어 보기: 판정과 무관하게 **모든 케이스를 '인수권 마지막 날 인수권 매수 + 청약'** 으로 진입했다고 보고
  관문1 통과/탈락 · 채무상환 비중 · 희석률 · 흑자 여부 · 괴리율 구간(H1)별로 같은 표
- 카드 손익표: 판정별 표본이 5건 이상이면 기본값(+15/0/−15/−30%) 대신
  '인수권 매수+청약 → 상장일 시가' 수익률의 75/50/25 퍼센타일·최저로 바뀐다 (`data/backtest.json` 의 `card_scenarios`)

- 전략 근거 ([18], `strategy_stats` → data/backtest.json `strategies`): 조건은 `strategy.conditions` 그대로.
  🥇🥉 = 비교 기준(인수권 매수+청약)과 같은 진입, 🥇 는 매도 유리 비율(+20일 수익률 < 0). 🥈 = 상장일 종가 진입 · ATR×2 손절 · +10거래일(연도 결과의 `s2`, 인수권 시세가 없어도 상장일 시세만 있으면 잰다). 금지 규칙은 +20일 비교 기준
  - 🥈 는 판정일(인수권 마지막 날) 기준 영업이익으로 조건을 본다 (상장일까지 새 보고서가 나올 수 있음 — 보수적). 상장폐지 종목은 상장 전 시세가 인수권 기간뿐이라 ATR·RSI 미확인 → 손절 없이 +10일

## 한계 (결과를 읽을 때 반드시 같이 볼 것)
- **인수권 비상장 주주배정은 파싱 대상에서 뺀다**: 원문에 '신주인수권증서의 상장여부 아니오'(최대주주 단독 배정 등)면 인수권 거래가 원래 없다 → `no_rights_listing`. `parse_rate` = 파싱 성공 ÷ (주주배정 − 인수권 비상장), `parse_rate_all` = 파싱 성공 ÷ 주주배정
- **옛 양식(2020 무렵)**: 유상증자결정 표엔 '상장여부 예'만 있고 인수권 기간은 '기타 투자판단' 문장("신주인수권증서 상장예정기간 : 날짜 ~ 날짜")이나 증권신고서 일정표("날짜 ~ 날짜 신주인수권증서 상장 거래기간")에만 있다 → 둘 다 읽는다(파서 v11)
- **DART 하루 한도**: 백테스트 전체 한 번이 DART 를 연도당 수천 건 부른다. 하루 한도(약 2만 건)를 넘기면 `DartQuotaError` 로 그해 실행이 실패하고 이전 결과가 남는다 — 전체 실행은 하루 한 번까지, 실패한 해만 다음 날 다시
- **한 번에 전부 돌리기**: Actions → "백테스트 전체 (연도 병렬)" → Run workflow. 연도별 job 이 동시에(최대 4개) 돌고 마지막에 한 번 합산·커밋한다. 실패한 해만 years 에 `[2023]` 처럼 넣어 다시 돌리면 된다. 한 해씩은 기존 `collect` 워크플로의 `backtest` 명령
- **판정 로직 버전**: 연도 결과마다 logic_version 을 적는다. 합산(data/backtest.json)은 지금 LOGIC_VERSION 으로 채점된 해만 넣고, 옛 버전 해는 `stale_years` 로 따로 표시(사이트 '재채점 필요') — 판정 기준이 바뀌면 그해 backtest 를 다시 돌린다
- **파싱 실패는 채점에서 빠진다** → 연도별 파싱 성공률을 사이트·JSON 에 표시. 옛 양식일수록 실패가 많을 수 있고,
  실패가 특정 유형(작은 회사·특이 양식)에 몰리면 결과가 치우친다
- 인수권 시세가 없는 케이스(기간 파싱 이상 등)도 빠진다 → `no_rights_price`
- 상장폐지 회사 중 DART 목록에 종목코드가 비어 나오는 경우는 잡히지 않는다 (생존편향 일부 남음)
- 상장폐지 종목은 52주 위치가 '미확인'(관문1을 막지 않음) → 그 케이스는 관문1이 더 쉽게 통과
- 최대주주 청약·인수방식은 원문 휴리스틱이라 미확인이 많다. 업계 순위·대체 불가는 자동화 불가(항상 미확인)
- 영업이익은 제출기한 기준이라 실제보다 한 분기 늦은 실적일 수 있다
- 판정 로직의 정정공시 필드(자금목적·희석)는 판정일 이후 정정까지 반영될 수 있다 (드묾)
- 표본 수가 작다 — 판정별 건수를 반드시 같이 본다. 매매 제한 문구는 넣지 않음(결정 15)
